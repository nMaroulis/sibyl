# Managed user-service contracts

`installation/services/` owns one user-level service with small native provider classes inheriting `UserService`: `LaunchdService`, `SystemdService` and `WindowsService`. `ServiceManager` owns explicit actions, nonsecret launch receipts, definition hashes, private writes, port preflight and ownership checks. No provider is imported through an agent runtime wrapper; no install/control action happens at module import or normal app startup.

`python -m sibyl service …` dispatches before application imports. Help/preview do not create a workspace or start the app. The existing foreground parser retains its behavior; `--log-file` configures native rotating logging handlers and `--no-access-log` disables HTTP access/query records. Service launch choices use an absolute interpreter/module, explicit workspace, loopback host and unprivileged port, with explicit `--env-file` or `--no-env-file`. Model/exchange credentials are never serialized into definitions/receipts, and no environment dictionary is copied. Workspace data is not migrated or removed.

## Native contracts

- [Apple LaunchAgents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html): user `~/Library/LaunchAgents/io.sibyl.dashboard.plist`, argument array, GUI UID domain, `RunAtLoad`, failed-exit KeepAlive, 30-second throttle and native stop timeout. Install writes/enables the next-login definition without bootstrap; Start bootstraps a fresh stopped definition; Stop persistently disables and boots it out.
- [systemd services](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html): XDG/user `sibyl.service`, `Type=exec`, user daemon reload/enable, `default.target`, SIGTERM/20-second shutdown and bounded failed-start burst. ExecStart arguments escape C-string, percent-specifier and dollar-environment syntax. All commands are argument arrays, never a shell. No system-level unit or linger setting is changed.
- [Windows Task Scheduler schema](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema) and [schtasks](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks-create): a SID-specific root task uses the current user's InteractiveToken and LeastPrivilege principal, login trigger, no execution time limit, IgnoreNew instances and bounded failure retries. UTF-16 XML and native Windows command-line quoting preserve paths. A constant PowerShell status query returns only allowlisted state/result/ownership; it is not a generated script containing user input. Native [hard termination](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-allowhardterminate) is disclosed. The sibling pythonw interpreter is used when available, with explicit stream-independent file logging.

## Ownership, failures and privacy

Definitions carry a format-version marker and a separate owner-readable JSON receipt with exact nonsecret launch choices and SHA-256. Reads validate structure/hash before allowing a new launch. Native registration path/source must agree with a marked local definition; foreign services are not controlled. Replacement is explicit and rejected while running. Terminal definition/receipt symlinks and unmarked files are refused. Hashes establish local consistency, not attestation against the workspace owner. Short atomic writes publish each file, not a distributed transaction with an OS manager. Crash/failed registration can leave files/accepted actions to inspect; there is no automatic mutating retry or destructive rollback.

Start checks loopback port availability before native start; the OS still arbitrates races. Already-running starts are idempotent. Stop disables future login startup; Restart refuses a still-stopping service. Uninstall stops/unregisters before removing only the managed files, retaining workspace/log contents. Native command errors/timeouts discard raw diagnostics because manager output can include environment material. Read status has a five-second command bound, control requests thirty seconds. Native output is filtered, not passed wholesale into HTTP or LLM evidence. Native running/PID/result values are separate from API health, worker progress and venue readiness.

Logs use standard-library RotatingFileHandler, max 5 MiB plus three backups, explicit noncolored formatters and restrictive process umask where supported. Access logging is disabled in service arguments, and root logging remains WARNING. Log paths are returned; log bodies are not included in status, diagnostics or agent tools. Logs can contain operational details and are not an automatic safe public artifact.

`GET /api/v1/workspace/service` is private/no-store and read-only. The collapsed Settings panel does not poll the OS; opening or manually refreshing requests status. The native Technician `background_service_status` tool reads this same domain function and setup guidance; it cannot install, start, stop or uninstall. Both identify workspace mismatch where a verified receipt exists. Windows reports Task Scheduler result separately from process exit codes and does not invent an application PID.

Acceptance uses temporary directories, fake native command managers and isolated foreground processes. Tests check definition structure, lifecycle arrays, no immediate start during install, quoting, unavailable versus absent state, current-user Windows binding, ownership/replacement, no mutating retries, stale definitions, occupied ports, retained data, nonsecret receipts, private rotating logs and native read-only HTTP/agent access. These do not prove an actual login/logout, host outage, upgrade or every OS policy. Those external lifecycle checks, prebuilt installers/signing, Homebrew and registry publication remain outstanding.
